# Korean Beauty — интернет-магазин корейской косметики

Магазин для **Korean Beauty** (г. Нукус, Узбекистан): каталог с фильтрами,
корзина, оформление заказа и админ-панель для управления товарами.

---

## Быстрый старт

```bash
npm install      # установить зависимости (один раз)
npm run seed     # заполнить каталог демо-товарами (один раз)
npm start        # запустить магазин
```

Откройте:

| Адрес | Что это |
|---|---|
| http://localhost:3000 | Магазин |
| http://localhost:3000/admin | Админ-панель |

**Вход в админ-панель:** логин `admin`. Пароль задаётся командой
`npm run password` — она выведет его в консоль один раз, сохраните его.
Сменить позже можно там же или в панели: **Настройки → Смена пароля**.

> При самом первом запуске, если пароль ещё не задавали, создаётся временный —
> он печатается в консоли при старте. Обязательно замените его перед тем,
> как открывать магазин наружу.

## Что умеет магазин

**Витрина**
- Главная: обложка, индекс брендов, разделы ухода, хиты, подбор по типу кожи, отзывы, доставка
- Каталог: фильтры по разделу, бренду, цене, типу кожи и задаче («акне», «пигментация», …),
  плюс «в наличии», «со скидкой», «новинки», «избранное»
- Сортировка: популярные, новинки, цена ↑↓, рейтинг, название. Пагинация.
- Поиск работает **и по-русски, и по-английски**: «тонер», «крем», «COSRX», «Snail»
- Карточка товара: галерея, вкладки (описание / применение / состав / доставка),
  похожие товары, разметка Schema.org для поисковиков
- Корзина в выдвижной панели, избранное (сердечки), прогресс до бесплатной доставки
- Оформление заказа: самовывоз или доставка, расчёт стоимости доставки,
  кнопка «Продублировать в Telegram» — заказ мгновенно уходит продавцу
- Адаптив: телефон, планшет, десктоп

**Админ-панель**
- Обзор: товары, заказы, выручка, заканчивающиеся позиции, топ продаж
- Товары: добавление, редактирование, удаление, скрытие, быстрая правка остатка,
  загрузка фото перетаскиванием (до 8 шт.), метки «хит» и «новинка»
- Разделы и бренды: полное управление
- Заказы: просмотр состава, смена статуса, связь с покупателем, удаление
- Настройки: телефон, Telegram, Instagram, адрес, часы работы, цена и порог бесплатной доставки

## Ежедневная работа

**Добавить товар:** Админ-панель → *Товары* → **+ Добавить товар**.
Обязательны только название и цена. Фото перетащите в поле загрузки.
Чтобы товар появился на главной в «Хитах», включите переключатель **Хит продаж**.

**Принять заказ:** новые заказы подсвечены в разделе *Заказы* (счётчик в меню).
Нажмите на строку — увидите состав, телефон и адрес. Меняйте статус по мере
выполнения: `Новый → Подтверждён → Доставляется → Выполнен`.

**Товар закончился:** поставьте остаток `0` прямо в таблице товаров. В каталоге
он останется видимым с пометкой «Под заказ», а кнопка предложит написать в Telegram.
Чтобы убрать совсем — нажмите кнопку с перечёркнутым глазом (скрыть).

**Поменять телефон или Telegram:** *Настройки*. Изменения сразу появятся
в шапке, подвале и на всех кнопках заказа.

## Дизайн-система

Магазин для женской аудитории, поэтому главные требования — **чисто и
максимально понятно**: тёплая пудровая палитра, крупный текст, явные кнопки
и поля, ничего не спрятано за наведением.

Все цвета — переменные в начале `public/css/style.css`:

| Токен | Значение | Для чего |
|---|---|---|
| `--paper` | `#FDFAF8` | фон страницы |
| `--blush` | `#F9EFEC` | пудровые секции, шапка первого экрана |
| `--surface` | `#FFFFFF` | карточки, поля, панели |
| `--ink` | `#2A211F` | основной текст, контраст 14.8:1 |
| `--ink-2` | `#5A4B47` | обычный текст, 7.6:1 |
| `--ink-3` | `#7A6864` | подписи, 5.0:1 |
| `--accent` | `#A65A63` | пыльная роза: кнопки, ссылки, 4.7:1 |
| `--gold` | `#9A7B3F` | второй акцент: бренды, рейтинг |

Шрифты: **Playfair Display** для заголовков, **Inter** для всего остального.
Базовый размер — 16px, цены и счётчики набраны моноширинными цифрами
(`tabular-nums`), чтобы колонки в таблицах не «прыгали».

**Правила понятности**, которым следует вёрстка:

- Кнопка «В корзину» и сердечко видны на карточке **всегда**, а не по
  наведению — на телефоне наведения не существует.
- Все поля ввода имеют рамку, фон и подсветку при фокусе: должно быть видно,
  что туда можно писать.
- Кликаемые элементы — не меньше 44×44 px.
- Контраст текста — не ниже 4.5:1.
- Появление блоков при прокрутке включается только если JS реально работает
  (класс `.js` на `<html>`). Если скрипт упадёт, содержимое останется видимым.

Иконки — только SVG из `public/js/icons.js` (витрина) и из объекта `I`
в `public/js/admin.js` (панель). **Эмодзи в интерфейсе не используются**: они
по-разному рисуются в Windows, Android и iOS, а флаги (🇰🇷) на Windows
вообще не отображаются — вместо них видны буквы «KR».

Чтобы добавить раздел со своей иконкой, допишите её в объект `ICON`
в `icons.js` под ключом, равным слагу раздела. Если иконки нет, подставится
нейтральная — ничего не сломается.

## Свой логотип

Положите квадратный файл `logo.png` (от 200×200) в папку `public/img/`.
Он автоматически заменит встроенный знак K&B на всех страницах.
Если файла нет — используется встроенный логотип, ничего не ломается.

## Данные и резервные копии

Весь магазин — одна база: товары, заказы, настройки, пароль администратора
и **фотографии** (они хранятся в самой базе, а не файлами).

| Где работает магазин | Где база |
|---|---|
| На своём компьютере, на VPS | файл `data/shop.db` |
| На Vercel или Render | Turso — адрес и токен в `KB_DB_URL` и `KB_DB_TOKEN` |

На Vercel и Render база обязана быть внешней: их диск не сохраняется.
Без `KB_DB_URL` магазин там не работает, а отвечает «временно недоступен» —
чтобы не принимать заказы, которые пропадут.

**Резервная копия — `npm run backup`.** Её можно делать на работающем магазине.
С заданными `KB_DB_URL` и `KB_DB_TOKEN` команда скачивает копию боевой базы из Turso.

Не копируйте `data/shop.db` вручную, пока магазин запущен: база пишет свежие
заказы в отдельный журнал (`shop.db-wal`), и копия, снятая посреди записи,
может оказаться повреждённой. `npm run backup` делает согласованный снимок
и сразу проверяет его целостность.

Копии складываются в `data/backups/`. Храните их и на другом устройстве.
Как восстановить — в [DEPLOY.md](DEPLOY.md).

## Команды

**Работа с магазином**

| Команда | Что делает |
|---|---|
| `npm start` | Запустить магазин |
| `npm run dev` | Запуск с автоперезагрузкой при правке кода |
| `npm run password` | Сменить пароль администратора |
| `npm run backup` | Резервная копия базы и фото — можно на работающем магазине |
| `npm run share` | Временная публичная ссылка с HTTPS |

**Перед выкаткой**

| Команда | Что делает |
|---|---|
| `npm run preflight` | Проверка готовности: что осталось сделать перед запуском |
| `npm run demo:clear` | Показать демо-товары; `npm run demo:clear yes` — удалить. Заказы не трогает |
| `npm run db:push` | Показать, что перенесётся в Turso; `npm run db:push yes` — перенести |

Подтверждение пишется словом **`yes` без дефисов**. Запись `-- --yes`
в PowerShell до команды не доходит — она молча выполнится как предпросмотр
и подскажет правильную запись.

**Проверки** (при работающем `npm start`)

| Команда | Что делает |
|---|---|
| `npm test` | API, админка, безопасность, превью ссылок — 104 проверки |
| `npm run test:browser` | Витрина в настоящем браузере: фильтры, корзина, избранное |
| `npm run audit:layout` | Вёрстка на 10 размерах экрана — от iPhone SE до 1920px |

**Опасные — только для разработки**

| Команда | Что делает |
|---|---|
| `npm run seed` | Заполнить пустой каталог демо-товарами |
| `npm run reset` | ⚠️ **Стирает всё: товары и заказы.** Не запускайте на живом магазине |

Если пароль администратора сменён, тестам нужно его передать:
`KB_ADMIN_PASS=ваш_пароль npm test` (Git Bash) или
`$env:KB_ADMIN_PASS="ваш_пароль"; npm test` (PowerShell).
Тест создаёт пару заказов и **удаляет ровно их** — ваши заказы не трогает.
Если подключён Telegram-бот, уведомления о тестовых заказах придут в чат.

`npm run audit:layout` ищет то, что не видно на одном разрешении:
горизонтальную прокрутку, текст мельче 12 px, кнопки меньше 30 px и элементы,
вылезающие за край экрана. Проверяются 320, 360, 390, 428, 768, 834, 1024,
1280, 1440 и 1920 px — то есть реальные телефоны, планшеты и мониторы.

Проверки запускайте при работающем `npm start`. Браузерный тест
поднимает Edge или Chrome в фоновом режиме и кликает по странице сам —
он ловит ошибки интерфейса, которые не видны на уровне API.

## Настройки запуска

Для разработки ничего настраивать не нужно. На сервере настройки задаются
в файле `.env` — образец со всеми пояснениями в **`.env.example`**:

```bash
cp .env.example .env
```

Главные:

| Переменная | Зачем |
|---|---|
| `NODE_ENV=production` | HSTS, журнал запросов, скрытые детали ошибок |
| `KB_PUBLIC_URL` | Адрес сайта — для карты сайта и превью в Telegram |
| `KB_DB_URL`, `KB_DB_TOKEN` | База Turso. Не заданы — файл `data/shop.db` |
| `KB_DATA_DIR` | Папка файловой базы и резервных копий |
| `KB_TRUST_PROXY` | Кому верить заголовки прокси: `loopback` на VPS, `cloudflare` на Render, на Vercel выставляется само. От этого зависят защита входа и лимит заказов |

Файл `.env` в git не попадает — это уже настроено. На Vercel и Render
переменные задаются в панели платформы, `.env` там не нужен.

## Уведомления о заказах в Telegram

Без этого заказ видно только в админ-панели. Настройка — 3 минуты,
всё внутри панели: **Настройки → Уведомления о заказах в Telegram**.

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, придумайте имя.
   Он пришлёт длинную строку с двоеточием — это токен.
2. Вставьте токен в панель, нажмите «Проверить токен».
3. Напишите своему новому боту любое сообщение.
4. Нажмите «Найти мой чат» и выберите себя. Придёт тестовое сообщение.

Дальше каждый заказ приходит вам сразу: состав, сумма, имя, телефон и адрес.
Токен хранится в базе и наружу не отдаётся — даже в списке настроек.

Если Telegram недоступен, заказ всё равно сохраняется: покупатель ничего
не заметит, а ошибка попадёт в лог сервера.

## Показать магазин людям без покупки хостинга

Временная ссылка с HTTPS через Cloudflare Tunnel — удобно, чтобы собрать
отзывы до настоящей выкатки.

```bash
npm start        # в одном окне — магазин
npm run share    # во втором — публичная ссылка
```

Во втором окне появится адрес вида `https://что-то.trycloudflare.com` —
его можно отправлять кому угодно. Закроете окно (Ctrl+C) — ссылка умрёт.

**Прежде чем открывать наружу:**

- смените пароль (`npm run password`) — иначе админку откроет любой желающий;
- если в каталоге ещё **демо-товары** — предупредите тех, кому показываете,
  или уберите их: `npm run demo:clear yes`.

## Выкатка в интернет

Пошаговая инструкция — в **[DEPLOY.md](DEPLOY.md)**. Три пути:

- **Vercel + Turso** — бесплатно, не засыпает, но тариф Hobby по правилам
  только для некоммерческих сайтов;
- **Render + Turso** — бесплатно, коммерция разрешена, засыпает без «будильника»;
- **VPS** — около $5 в месяц, свой сервер без ограничений бесплатных тарифов.

Коротко, что сделать у себя перед этим:

```powershell
npm start
npm run preflight          # что осталось
npm run demo:clear yes     # убрать демо-товары (заказы останутся)
npm run backup             # копия перед переносом
```

Готовые файлы для сервера:

| Файл | Для чего |
|---|---|
| `app.js`, `vercel.json` | Vercel: точка входа и регион Токио (рядом с базой) |
| `render.yaml` | Настройки Render: бесплатный тариф, Сингапур (рядом с базой в Токио), проверка здоровья |
| `.env.example` | Образец настроек со всеми пояснениями |
| `Dockerfile` | Для Docker |
| `deploy/korean-beauty.service` | Служба systemd: автозапуск и перезапуск при сбое |
| `deploy/korean-beauty-backup.*` | Ежедневная резервная копия в 03:30 |
| `deploy/nginx.conf` | nginx перед приложением, HTTPS добавит certbot |

## Безопасность

- Пароль хранится в виде scrypt-хеша, а не текстом.
- При первом запуске пароль администратора **случайный** и печатается один раз.
- После 5 неудачных попыток входа адрес блокируется на минуту, дальше пауза
  удваивается. **Подменить свой IP заголовком нельзя:** приложение верит
  заголовкам `X-Forwarded-*` только от своего прокси (`KB_TRUST_PROXY`).
  На Render доверие идёт по адресам Cloudflare и внутренней сети, а не по
  числу прокси: при ошибке на единицу все покупательницы слились бы в один
  адрес (подробно — `server/proxy.js`).
- Не больше 5 заказов за 10 минут с одного адреса — бот не засыплет
  магазин и ваш Telegram.
- Cookie сессии недоступна скриптам (`HttpOnly`), получает `Secure` на HTTPS.
- На HTTPS в продакшене включается HSTS.
- Заголовки `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`,
  `Permissions-Policy`.
- Все запросы к базе — через подготовленные выражения.
- Загружать можно только изображения до 4 МБ, тип проверяется по содержимому
  файла, а не по расширению. Браузер перед отправкой уменьшает снимок до 1400 px
  и отправляет фото по одному.
- Токен Telegram-бота не отдаётся наружу и не перезаписывается через общие настройки.
- Зависимости проверены `npm audit`: уязвимостей нет.

## Превью ссылок в Telegram

Когда ссылку на магазин или товар присылают в Telegram, появляется карточка
с названием, ценой и картинкой. Для этого сервер сам вписывает мета-теги в
страницу: Telegram, WhatsApp и поисковики JavaScript не выполняют.

- Главная и разделы — общая картинка `public/img/og-image.png`.
- Товар — его фото, если оно загружено в JPG, PNG или WebP.
- Telegram запоминает превью. Если оно устарело, отправьте ссылку боту
  **@WebpageBot**.

## Устройство проекта

```
app.js             точка входа для Vercel (подключает server/index.js)
server/
  index.js         запуск, маршруты, заголовки, корректная остановка
  config.js        настройки из переменных окружения и .env
  db.js            база: файл SQLite или Turso, схема, фото, настройки магазина
  http.js          ошибки асинхронных маршрутов — в общий обработчик
  auth.js          пароли, сессии, защита от подбора пароля
  proxy.js         определение IP покупательницы за Cloudflare (Render)
  ratelimit.js     ограничение частоты: заказы, загрузка фото
  cli.js           флаги служебных команд (yes, replace, from=)
  seo.js           мета-теги и превью ссылок
  notify.js        уведомления о заказах в Telegram
  routes/
    api.js         публичное API: каталог, фильтры, корзина, заказы
    admin.js       API админки: товары, разделы, бренды, заказы, фото
  backup.js        резервная копия       (npm run backup)
  db-push.js       перенос базы в Turso  (npm run db:push)
  preflight.js     проверка готовности   (npm run preflight)
  demo-clear.js    удаление демо-товаров (npm run demo:clear)
  password.js      смена пароля          (npm run password)
  share.js         публичная ссылка      (npm run share)
  seed.js          демо-каталог          (npm run seed)
  smoke.js         проверки API          (npm test)
  browser-test.js  проверки в браузере   (npm run test:browser)
  layout-audit.js  проверка вёрстки      (npm run audit:layout)
views/              страницы: сервер вписывает в них мета-теги для превью
  index.html, catalog.html, product.html, checkout.html, privacy.html, 404.html
  admin.html        админ-панель
public/             раздаётся как есть (на Vercel — мимо сервера)
  css/              style.css (витрина), admin.css (панель)
  js/               icons.js, app.js, home / catalog / product / checkout / admin
  img/              og-image.png (превью), favicon.svg, products/ (заглушки демо)
deploy/             systemd, nginx для VPS — см. DEPLOY.md
vercel.json         настройки Vercel: регион, заголовки
render.yaml         настройки Render
```

Страницы лежат в `views/`, а не в `public/`: Vercel отдаёт `public/` сам,
не спрашивая сервер, и в превью ссылок не попали бы название и цена товара.

Технологии: Node.js 22 + Express, SQLite через `@libsql/client` — один и тот же
код работает и с файлом, и с Turso. Фронтенд — обычные HTML/CSS/JS без сборки.
Зависимостей пять: `express`, `@libsql/client` (база), `multer` (загрузка фото),
`compression` (сжатие) и `@vercel/functions` (уведомления о заказах на Vercel).
